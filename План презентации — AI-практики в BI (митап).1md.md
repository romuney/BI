### Драматургия: три акта

- **Акт I «Мир изменился» (~4 мин)** — почему сейчас момент: модели нового поколения (DeepSeek V4, GLM-5.3) сделали агентные сценарии рабочими, а не демонстрационными.
- **Акт II «Карта инструментов» (~18 мин)** — систематизация по четырём уровням: Платформа → Среда → Личный агент → Экосистема. Содержательная основа доклада.
- **Акт III «Что делать вам» (~5 мин)** — практический чеклист, с чего начать завтра, что на горизонте, призыв контрибьютить скиллы.

### Сквозная метафора

Четыре уровня зрелости AI-инструментов аналитика — «лестница»:
на нижней ступени AI отвечает на вопросы (ассистент), на верхней — AI выполняет рутину за тебя (скиллы и автоматизация).
Каждый блок акта II — одна ступень. Визуально: одна и та же схема-лестница повторяется на разделителях секций, подсвечивается текущий уровень.

### АКТ II. «КАРТА ИНСТРУМЕНТОВ» — слайды 5–20 (~18 мин)

#### Раздел A. Helicopter — слайды 5–7

#### Слайд 5. Разделитель: уровень «Среда» + Helicopter в 30 секунд
- **Тезис**: Helicopter — это IDE для работы с данными: ноутбуки, кроны, и ИИ живёт прямо в панели.
- **Контент**: helicopter.tcsbank.ru; ноутбуки на расписании (кроны с датами начала/конца); Nessy Data Agent — правая панель любого ноутбука; с 18.09 главная страница — **Nessy Data Workspace**: чат видит несколько ноутов и таблиц, панель «Артефакты» (анонс собрал fire×17, rocket×9).
- **Визуал**: скриншот интерфейса Helicopter с подсвеченной правой панелью.
- **Заметки**: 1 мин. Не туториал по IDE, а мост к следующему слайду. Стратегическая цель платформы (цитата из чата helicopter-users, 10.09): «Мы хотим, чтобы в компании агентом закрывался е2е процесс работы с данными — от запроса до создания дашборда».

#### Слайд 6. Nessy Data Agent: SQL из текстового описания
- **Тезис**: Описываешь выгрузку словами — получаешь SQL; не знаешь таблиц — агент сам найдёт их в DWH.
- **Контент**: структура промта, которая работает: Роль → Контекст задачи → Период → Поля → Таблицы (или «найди сам») → Формат результата. Пример «плохого» и «хорошего» промта. Правило: Nessy — ассистент, ответственность за запрос на аналитике (проверяй через LIMIT 100, дедублируй).
- **Визуал**: два промта рядом (❌ «дай данные по судам за год» / ✅ структурированный) → стрелка → SQL.
- **Заметки**: 1,5 мин. Источник: инструкция «Nessy Data Agent в Helicopter для написания SQL» (wiki 9035808218). Подчеркнуть итеративность: «добавь фильтр», «убери дубли».

#### Слайд 7. Кейсы Helicopter из практики
- **Тезис**: Команды уже экономят часы на выгрузках — и не только на SQL.
- **Контент** (реальные кейсы из Time-чатов): (1) агент как справочник по внутренним библиотекам — «у него в контексте документация по dal и другим либам» (helicopter-users, 02.07); (2) тред на 77 постов про е2е-сценарий «запрос → ноут → крон → дашборд»: часть уже в агенте, MCP для ноутбуков — план Q4 (helicopter-users, 09–10.09); (3) скилл в Helicopter, отдающий селект и конечный ответ по текстовому запросу (bi-analytics, 04.09); (4) анализ «Выписок» банка через агентов с тюнингом промптов (Nessy CLI Discussion, 17.09).
- **Визуал**: карточки кейсов «было → стало».
- **Заметки**: 1 мин. Живые имена команд работают лучше цифр. Все кейсы — из Приложения А.2.

#### Раздел B. Proteus AI — слайды 8–9

#### Слайд 8. Proteus AI: агент на вашем дашборде
- **Тезис**: На каждом дашборде живёт агент, который отвечает на вопросы по данным — а скиллы дашборда учат его контексту именно вашего борда.
- **Контент**: скилл = дополнение к системному промпту агента (какие метрики смотреть, фильтры по умолчанию, как интерпретировать); создаётся через чат с агентом; скилл доступен **всем пользователям дашборда**; структура: name, description, prompt. Реальность шире скиллов: с 20.08 на дашбордах кнопка **«AI-анализ»** — агент анализирует данные графиков с учётом метрик, настроек и нативных фильтров («вы активно им пользуетесь» — из анонса); в саппорт-каналах proteus-users бот платформы публикует «Текст ответа от AI-помощника» прямо в тредах обращений; агент правит eCharts-код графиков.
- **Визуал**: скриншот Q&A на дашборде + карточка структуры скилла.
- **Заметки**: 1,5 мин. Кейсы из Time (Приложение А.3): команда отказалась от самописного бота в тайме в пользу скиллов Proteus AI («из любого борда запросить значение любой метрики в нужных разрезах», bi-analytics 07.09); в треде про селф-сервис метрик откликнулись 8+ команд. Прямой призыв: «Если ты владелец дашборда — сделай борд самообъясняющимся. Один вечер».

#### Слайд 9. Proteus AI: честно о границах
- **Тезис**: Интеграция со Skills Market и GitLab пока в бэклоге — скиллы в Proteus AI создаются через чат; это временно.
- **Контент**: таблица «работает / не работает»: ✅ создание и редактирование скиллов через чат (владельцы бордов), ✅ скилл виден всем пользователям борда; ❌ установка из Skills Market / GitLab (RFC «Proteus Agent 🤝 Skills Market» в проработке, автозагрузка — PROTEUS-918), ❌ автоактивация скилла (в работе), ❌ UI редактирования («скоро»).
- **Визуал**: две колонки ✅/❌.
- **Заметки**: 1 мин. Слайд про доверие: «Я вам не продаю — я показываю, где границы. Планы такие-то». Это усиливает всё остальное.

#### Раздел C. Личный агент: tclaude и BYOK — слайды 10–12

#### Слайд 10. tclaude: корпоративный кодинг-агент
- **Тезис**: T-Claude Code — это Claude Code от Nestor: песочница, LLM Proxy, Анон и корпоративные MCP-инструменты из dp cli — агент умеет читать Proteus, Jira, GitLab, Sage, Wiki, T-Tracker.
- **Контент**: что это даёт BI-аналитику: агент читает твой дашборд через MCP Proteus (состав, SQL графиков, фильтры), правит скиллы борда, ходит в Jira/Tracker за задачами, ищет по wiki. Доступ — место в ai-seats через руководителя, группа ai-coding-wave1.
- **Визуал**: скриншот терминала tclaude + иконки MCP-интеграций вокруг.
- **Заметки**: 1,5 мин. Пример из практики: «спрашиваешь агента “что считается в этом графике” — он читает SQL графика и объясняет».

#### Слайд 11. BYOK: свой ключ в корпоративном tclaude
- **Тезис**: К tclaude можно подключить личную модель по своему ключу — и GLM сегодня единственная внешняя модель, которую согласовала ИБ.
- **Контент**: три пути: (1) общая Team-подписка Claude (оформляем мы); (2) своя подписка Claude/ChatGPT (AD-группа Sandbox); (3) **GLM Coding Plan в tclaude** — втрое дешевле Claude, модели GLM-5.3 / GLM-5.3-Flash, контекст 1M, тарифы $18/$80/$168 в месяц; ключ z.ai идёт заголовком через LLM Proxy → трафик проходит Анон и корпоративные гарды, место в ai-seats не нужно. Границы ИБ: только рабочая станция, только tclaude, не для прода/CI. С 0.0.23 есть официальная команда `tclaude set-byok-key`.
- **Визуал**: схема «z.ai-ключ → LLM Proxy (Анон, гарды) → tclaude» + таблица тарифов.
- **Заметки**: 1,5 мин. Источники: инструкция «Получение Claude Code/ChatGPT/GLM» (wiki 9112708455) + данные из Time-канала ~t-claude-code-byok-byol (см. Приложение А): запуск 04.09.2026, встреча сообщества 14.09 собрала **68 участников**; реальный опыт: Lite «не вариант» (5-часовой лимит уходит на одну задачу), Max — 70% недельных кредитов за 2 дня интенсивной работы → советовать Pro; латентность через прокси 9–10 сек на первый токен, пик 9:00–13:00 МСК. Грабли: суффикс `[1m]` обязателен, нужны ДВА ключа (персональный LLM Proxy + X-Byok-Key z.ai).

#### Слайд 12. Модельный ландшафт: что под какую задачу
- **Тезис**: Не существует «лучшей модели» — существует правильная модель под задачу и бюджет.
- **Контент**: сравнение: Claude (корпоративная квота ai-seats — тяжёлые задачи; дневной лимит extra-limits поднят до $150) / GLM-5.3 (личная подписка, 1M контекст, «скорость просто офигенная, всё летает» — реальная цитата из Time) / DeepSeek V4 Flash (под капотом Nessy — ежедневная рутина). Паттерн экономии из сообщества: flash на рутину и субагентов, 5.3 на планирование и ревью; оркестрация субагентов через CLAUDE.md.
- **Визуал**: таблица 3 колонки: строки — модель, чей бюджет, контекст, сильные стороны, когда брать.
- **Заметки**: 1 мин. Данные из Time-чатов (Приложение А): GLM Max хвалят за скорость и качество «лучше ожиданий в сравнении с Anthropic»; местный DeepSeek «раза в 4–6 медленнее» GLM на тестах; специализация: «для frontend qwen лучше… GLM больше для бэкенда». ВАЖНО для зала: сообщество BYOK пока чисто девелоперское — аналитиков там почти нет, доклад должен это поменять (см. Приложение А, «белое пятно»). Мост к следующему слайду: «А теперь — почему DeepSeek в этом ряду вообще появился».

#### Раздел D. Nessy → DeepSeek — слайд 13

#### Слайд 13. История одного переезда: Qwen → DeepSeek V4 Flash
- **Тезис**: Переезд Nessy на DeepSeek V4 Flash — это тот момент, когда агентные скиллы перестали быть лотереей.
- **Контент**: анонс от 31.08 (дословно из helicopter-announcements): «Прощай Qwen, привет Deepseek. Мы перевезли Nessy Data Agent на новую основную модель — deepseek-v4-flash-0731. Она новее, выше, сильнее. Иными словами, работает лучше прошлой». Техническая сторона: Qwen3.5 397b морально устарел → Q3-обновление; катали a2a (без проблем), затем nessy-cli; скачок нагрузки — стабилизировали в день инцидента; уроки ретро: гранулярная перекатка, бенчмарки не отражают реальность — решает фидбек бета-тестеров. Пользовательское эхо (Nessy CLI Discussion, 22.09): «superpowers работают, особенно после заезда на deepseek — когда qwen был, то не работало».
- **Визуал**: таймлайн переезда + две цитаты (анонс команды и отзыв пользователя).
- **Заметки**: 1,5 мин. Практический вывод для зала: «Если вы раньше пробовали скиллы в Nessy и они не работали — попробуйте ещё раз: это не те скиллы и не та модель». Источники: ретро перехода (wiki 9242349163), Time-каналы (Приложение А.2). Честная оговорка для Q&A: квоты суточные, при исчерпании — очередь; локальный DeepSeek медленнее GLM на тяжёлых задачах («раза в 4–6» на тестах).

#### Раздел E. n8n — слайд 14

### А.5. Hermes vs Nessy — шпаргалка (собрано 23.09.2026 из wiki + Time)

**Что такое Hermes.** Personal Agent — продукт ML Core: **Hermes Agent + Hermes UI**, персональный ИИ-агент **в облаке, формат чата прямо в браузере** — personal-agent.t-tech.team/hermes. В основе — открытый агент **Nous Research hermes-agent** (MIT, Python; коллеги запускают его и на личных компьютерах: «дома юзаю hermes-agent + glm — быстро работает»). Развитие — Jira MLP-14436; цикл обновлений активный (v0.21.1 → v0.21.3 за неделю сентября).

**Чем отличается от Nessy.** Nessy — это семейство локальных/платформенных агентов: Nessy CLI (кодинг-агент на рабочей станции, форк qwen-code на upstream, main-модель DeepSeek V4 Flash), Nessy Data Agent (в панели Helicopter, платформенное окружение с предустановленными аналитическими скиллами), Nessy Cloud. Hermes — облачный и персональный: сессия живёт ~10 часов (временное окружение, без крона и шэринга), **нет доступа к локальным файлам на ноуте**, зато нулевой порог входа — не нужен терминал.

| | Hermes (Personal Agent) | Nessy (CLI / Data Agent) |
|---|---|---|
| Где живёт | Облако, чат в браузере | CLI — на рабочей станции; Data Agent — в Helicopter |
| Локальные файлы на ноуте | ❌ | ✅ (CLI) |
| Statist / картинки / правка вики | ✅ | ✅ |
| Порог входа | Открыть ссылку | Установить CLI / открыть Helicopter |
| Время жизни | ~10 часов, временное | Персистентное |
| Аналитический режим | data-agent профиль | Nessy Data Agent (Helicopter) |
| Основа | Открытый hermes-agent (Nous Research) | Форк qwen-code |

Источник сравнения возможностей — вики-таблица «Отличия ИИ-агентов» (pageId=9260988814): Nessy CLI — единственный из тройки с доступом к локальным файлам; Copilot agent — без изображений и локальных файлов.

**Скиллы в Hermes (важно для слайда 17):** ставятся тремя способами — из Skills Market (`dp skills install <name> --agent hermes --profile default`, только V1-профиль; `-a all` Hermes не включает — таргет явно), git clone самим агентом, **создание прямо в UI** (чего пока нет в Nessy). После установки — `/reload-skills`. Т.е. Hermes — третья целевая среда валидации скиллов пака (Nessy CLI, Data Agent, Hermes).

**Как люди выбирают (Time, Nessy CLI Discussion, 23.09):** вопрос «пытаюсь научить ИИ-агента hermes **или** nessy читать параметры событий в Statist» — сообщество воспринимает их как sibling-среды: одна и та же задача, разный рантайм.

**Зачем это в докладе:** Hermes — это «нулевая ступень» лестницы инструментов для аналитика без терминала: открыл браузер → агент уже скиллы поддерживает. Упомянуть на слайде 21 (чеклист «с чего начать») как самый простой первый шаг и на слайде 17 как третью среду пака. Полная таблица — источник для отдельного слайда, если захочешь расширить карту.
